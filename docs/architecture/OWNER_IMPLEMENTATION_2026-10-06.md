## Ownership and trust boundaries

Local Yuki owns canonical identity, Personality Capsule, primary relationship, immutable evidence, revisioned memory, affect, life records, autonomy policy, capability decisions, action journal and recovery. SQLite physical schema is now 9, with explicit adjacent migrations from 1 through 9. Model role bindings refer to replaceable private files and immutable admission receipts. Neither runtime code nor model output receives the continuity database or Android capabilities.

The low-power process persists observations, pending concerns, intentions, topics, curiosity, preferences, opinions, self/relationship state, reflection conclusions and opinion revisions. Original evidence remains factual authority. Raw hidden model reasoning is not retained. Structured reflective conclusions and their evidence references are retained. A model saying something creates evidence of its utterance, not proof of an external event.

The production conversation path is real System One → optional System Two → trusted prepared meaning → real expression. No production mock fallback impersonates successful inference. System One contributes routing, confidence, salience, affect and bounded life-record proposals. System Two proposes conclusions and at most two typed actions. Only the Executive Action Controller can dispatch actions; it rechecks live grants and the Resource Governor. Language receives prepared points and a compact uncertainty flag, without memory writers, tools or grants; full uncertainty text stays in app-owned prepared meaning and is appended verbatim to the final reply. Point-index validation and verbatim uncertainty preservation enforce structural boundaries; they cannot mathematically guarantee that arbitrary generated prose is faithful. Owner behavioral evaluation remains necessary.

## Executable model system

Installed adapter `llama-cpp-cpu-b5046`, adapter version 3, vendors upstream llama.cpp b5046 / `74d4f5b041ad837153b0e90fc864b8290e01d8d5`, with license and provenance in `app/src/main/cpp/vendor/llama.cpp/UPSTREAM.txt`. ARM64 and x86_64 CPU builds are supported. GPU/NPU/offload is zero; no acceleration is falsely inferred from the phone's hardware. Format recognition is never admission. ONNX, safetensors, split GGUF and multimodal projection pairs have no installed executable adapter and cannot be admitted.

Models → Import uses Android's document picker, streams into private storage under a disk-headroom and 4 GiB cap, hashes the file and performs bounded GGUF metadata/tensor inspection. Architecture, parameter count, quantization, context and grouped-query KV geometry are recorded where available. Malformed dimensions, excessive metadata, arithmetic overflow, impossible declared weights and split models fail closed. The manifest remains inspectable for recognized-but-incompatible files.

Choose a supported role and Benchmark/admit. The app rehashes, checks actual memory/thermal/battery/foreground state, picks the versioned installed adapter, computes conservative weight/context/KV costs, and runs real inference in a private Android isolated process. The benchmark records startup/inference latency, tokens/rate, peak process memory, thermal before/after, selected context/threads/batch/backend and confirmed unload. Embedding admission additionally compares related/unrelated sentences. Embedding windows are capped at 512 tokens; mean-pooled encoder/decoder execution uses a complete-window batch, recorded separately from the requested decoder batch. Structured decision/reason/language contracts are tested. Runtime failure, malformed output, oversize cost, insufficient resources, hash change or failure to unload rejects admission. A receipt documents both acceptance and rejection. Successful receipt, manifest and role activation commit atomically; inference requires a matching immutable receipt as well as current file/adapter validation.

An admission is evidence of executable role compatibility and a measured safe envelope, not comprehensive model intelligence. Every inference checks current file identity and adapter version, obtains a governor lease and validates output. Each distinct private file is fully hashed/inspected per bounded turn; unchanged same-file fingerprints may reuse inspection only within that turn, with opened-descriptor verification before handoff. Models cannot self-modify grammar or resource caps. The isolated child receives only a read-only file descriptor and bounded input. Adapter v2 validates and duplicates that descriptor, parses metadata from its open stream and maps the same descriptor; it never reopens `/proc/self/fd` or an app-private pathname. Internal duplicates close after load/failure; unload releases mappings. Deadline/abort callbacks, a process watchdog, fresh pressure monitoring and parent cancellation unload or terminate the child. Operation cancellation also prevents a later bind/pass/admission/action proposal after Stop; the isolated child waives binding priority so optional inference can be reclaimed before the owner surface. No model stays resident between invocations; this is intentionally conservative and incurs repeated startup cost.

The owner may bind the same GGUF to several roles. Execution is serialized, so shared weights never imply redundant permanently resident copies. Role replacement changes performance/expression, not identity. Disable removes a role binding; unload cancels active native work; remove requires roles disabled and deletes only private weights, retaining history/receipts. Vault restoration retains role metadata but requires weights to be supplied and readmitted in the new body.

## Resource adaptation

Measured Android signals include actual available/total memory and low-memory state, battery/charging/power-save, thermal status, ABI/CPU concurrency, visible owner interaction, and fresh Accessibility/Usage Access foreground package where granted. Unknown/stale body signals constrain or defer work rather than assuming a flagship capability.

Profiles distinguish low-power/background/interactive/thinking, thermal-limited, memory-pressure, conservation and recovery behavior. Normal foreground inference is capped at a 4096-token context, 256 output tokens, four cognitive passes, 30 seconds, up to four CPU threads and a bounded batch. The envelope is reduced by trained context, admitted measurements and current resources. Measured loading and fixed prompt preparation are reserved once, with separate generated-token timing setting a conservative output budget with 40% generation headroom; generation unable to support a 64-token structured response in the admission envelope is refused. Subsequent passes also inherit the remaining total-turn deadline and never exceed the admitted output budget. Conservative memory budgets are at most 2 GiB, at most half measured available RAM, and preserve at least 512 MiB headroom. Constrained profiles shorten context/output, reduce passes/threads/batch and suspend optional inference/index work. Leases serialize neural cognition; model startup and prefill are part of the deadline. Context truncation is explicitly surfaced as uncertainty and prohibits new memory/action proposals from omitted context.

A visible conversation can temporarily request cognition, but cannot override thermal/memory safety. Model work stops when the owner surface backgrounds, Android trims memory, power save activates, or fresh native monitoring observes unsafe pressure. Expensive background neural inference is deferred. Background presence survives in app-owned state and coarse OS-scheduled jobs. Dynamic context adapts to resources, never grows beyond an admitted safe context. Actual hardware temperature is not available as a universal precise sensor; recorded thermal status is the Android signal.

## Android authority and embodiment

Owner controls distinguish the app policy switch from the actual Android grant. Setup opens the correct Android screen for Accessibility, notification listener, usage access, overlays, microphone, notifications or document-tree access. Both are required where applicable. No root/Device Owner/Shizuku authority is advertised or required.

Available typed operations include app-owned notes; foreground screen structure; package/category notifications; offline TTS; owner-initiated offline speech; app launch intents; navigation; bounded node click/set-text/scroll; media play/pause; explicitly selected document-tree filename search; notifications; companion overlay; bundled image/screenshot OCR; and authenticated Lockdown control. OCR reports text only, not scene understanding. Sensitive/password nodes and authority-management screens are excluded from UI interaction. Changing target package, ambiguous node, revoked permission or unavailable executor fails closed. A launch receipt reports intent dispatch, not unobserved success.

Every external operation has an intent ID, capability, current grant decision, selected executor, result and immutable grounded TOOL_RESULT. A durable pre-dispatch audit prevents unsafe retry after process death. Unknown interrupted operations are never reported successful or silently replayed. Deferred plans are bounded, tied to immutable owner-input evidence, claimed before dispatch and blocked by current grants/policy/quiet hours/resource pressure. Stop cancels active optional cognition and speech; sleep pauses cognition/recovery consistently.

Visible-app wake phrase uses Android's real offline recognizer and stops on app background/resource pressure. It is not an always-listening background hotword DSP. Android controls whether an offline speech service is installed. Notifications/overlays use actual platform grants and delivery results. JobScheduler uses persisted, battery-aware coarse jobs plus boot/package-update rescheduling; force-stop, Doze and Samsung battery restrictions can delay or stop delivery. No polling loop promises impossible process immortality.

## Persistent life and semantic memory

Life records are revisioned, evidence-linked and bounded. Opinion changes retain the previous opinion and evidence; append operations cannot branch or overwrite history. Pending concern selection prevents reflection-history starvation. Low-cost background cognition notices actual permission-backed events, revisits unresolved records, and persists conclusions/questions before initiating. When asked about absence, verified reflection records are part of conversation context. Initiative defaults off, with owner-configurable channels, quiet hours, urgency threshold, cooldown, daily saturation and per-topic deduplication. In-app records survive notification denial or process death.

Semantic vectors are derived, normalized and replaceable. A changed embedding hash or memory revision invalidates the affected derived vector, never the evidence. Maintenance indexes one eligible memory at a time after owner writes or via the Models control, within current resources. Recall is bounded and explicitly partial; lexical retrieval remains available when embeddings are absent/deferred. No reranker is installed because its extra memory cost has not been justified by phone measurements.

## Secure Lockdown bridge

Yuki Lockdown 1.8 exposes one versioned ContentProvider protocol at `com.mavyy.yukilockdown.localyuki.v1`. Binder caller UID must resolve exclusively to Local Yuki's package with its established pinned signing certificate. Lockdown's explicit allow-control toggle must be enabled. Local Yuki independently pins Lockdown's provider package and original certificate on each call. The existing apps have different signing keys; certificate-pinned Binder IPC preserves those keys rather than substituting an invalid same-signature permission assumption. Unrelated, shared-UID, unsigned/wrongly signed callers are rejected before parsing commands. Generic exported CRUD is forbidden.

Commands inspect current full state, mutate protected apps/domains/plans and limits/schedules through typed validated config, set control modes, configure companion enablement/wander/size/position, set reduced motion/dialogue/reaction, reset attempt counts, end breaks, and begin/confirm temporary bypass through Lockdown's own same-boot minimum countdown. Every mutation includes expected state digest, command/request identity and durable receipt. Response version/identity/command/state digest are validated. Optimistic compare-and-set protects owner edits; idempotent receipts prevent duplicate mutation and interrupted claims refuse blind replay. Lockdown retains safe-app and rule/bypass invariants. No banked-time subsystem exists in the audited live app.

Robolectric authentication, protocol, state, idempotency, stale digest, settings bounds/countdown and schema tests are automated. Actual two-app Binder identity, overlay and guard behavior require installation of the two established signatures and owner device acceptance.

## Vault and migration

Vault uses the existing authenticated encrypted envelope with physical schema versions 1–9 supported. Restore decrypts a private candidate, migrates adjacent versions, checks SQLite integrity/foreign keys/exact schema and canonical identity, verifies immutable evidence digests/provenance and structured continuity records, then replaces the database atomically. Failed validation retains the current database. Signing keys, Android secrets and model weights are never identity-transfer requirements.

Identity/personality/relationship, raw history/evidence, durable and living memory, affect/associations, state/recovery, life/opinion history, reflections, pending plans, autonomy configuration, resource/capability policies and model manifests/receipts travel as app-owned continuity. Derived semantic vectors/body observations are cleared for reconstruction; role activation, external capability policy and autonomy are disabled for fresh-body review. Models must be reimported/readmitted. Resource limits and live Android grants are measured anew, never inherited as authority.
