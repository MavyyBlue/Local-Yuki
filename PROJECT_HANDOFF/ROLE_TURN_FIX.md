## File integrity and continuity

Each distinct private model file receives a full SHA256 and GGUF inspection on first use in every turn. Subsequent roles can reuse that inspection only for the same path, expected descriptor/digest and unchanged filesystem fingerprint: device/inode, size, mode, UID/GID, link count, and modification/change timestamps including nanoseconds. The selected read-only descriptor is fingerprint-checked immediately before Binder handoff. Symlinks and hardlinks fail the private-file check. Modification, replacement or changed expectations invalidate reuse; a file changed during inspection fails closed. Android26, which lacks these nanosecond stat fields, performs full inspection every pass. Distinct copies are separately hashed even if their expected hashes match.

The memo lives only in the bounded turn and is discarded at its end. No persistent trust cache, model deduplication, chmod, DB migration, identity rewrite or data reset is introduced. CPU adapter v3, existing files/receipts, schema9, signing keys and workflow protections remain. Diagnostics add `integrityReused`, `turnRemainingMs` and `turnLimitMs` alongside the individual organ deadline and existing timing/unload data.
